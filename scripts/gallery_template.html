What the whole Virtual Boy library actually draws

Every ROM in the corpus, recompiled to C and booted through the shared driver with no game-specific glue, with the action buttons held in bursts so the boot gates open. Each was sampled at frame 300, 600 and 900; the strips show only the distinct frames, labelled with the samples they cover — so a single image marked 300–900 is a game that drew once and never changed again.

What the strips show

  1. fixed

    A function made out of a call’s arguments

    Galactic Pinball wrote tiles and background maps and still drew nothing, because it never wrote a single world attribute. Its jal 0x07F417B8 is a long-call helper that reads its arguments inline from the bytes after the call site; those eight argument bytes had a function made out of them and were decoded as code, and the first halfword, 0x9800, decodes as bp . — a branch to itself. The caller fell in and spun there for the whole run. Detecting the idiom from the add N, r31 before jmp [r31], and refusing to split anywhere that is not an instruction boundary, took it from 1,232 to 9,442 non-zero character writes and from a blank screen to a picture.

  2. fixed

    The pad only updated when a game asked

    SDLR/SDHR returned a snapshot refreshed only when a game wrote SCR_START. The VB can also read the pad itself, and a game relying on that never writes START — so every button read returned zero for the entire run. Jack Bros composes the pad into an event word and stores its rising edges as the kernel’s dispatch flags; its scheduler is called only when those flags are set. A pad frozen at zero has no edges, so in a 700-frame run the flags were written three times and always as 0, and every task that loads graphics never ran.

  3. fixed

    Epilogues that were emitted nowhere

    The long-call idiom — jal .+4, add N, r31, jmp [rX] — returns to the address r31 now holds, but the analyzer treated the jmp as the end of the flow, so everything after it was never traced. SPONG’s virtual-dispatch thunks each lost their entire epilogue, and every virtual call in the game returned into a hole.

  4. measurement

    Half of what looked like regressions was pacing

    A frame is a count of vb_interrupt_check() calls, and that is emitted at every function entry — so any change to how the ROM is carved into functions silently changes the frame rate. One control-flow change looked like it destroyed Elevated Speed (231,461 non-zero character writes down to 7,667) and at a higher tick count produces 221,142. Nothing was miscompiled. Every control-flow measurement here has to be taken at more than one tick count before it is called a regression.

  5. blank

    Five of these ROMs cannot render at all

    Capitan Sevilla 3D, Null Pointer Mockup and the three Snowball Wars demos draw nothing on the reference emulator either, checked at three times this page’s frame budget with the same buttons held. Capitan Sevilla and Null Pointer load character data and never draw it; the Snowball Wars demos never load any. They are inert ROMs, not games being run badly.

  6. blank

    The five that are ours, and they are not one bug

    SPONG, Formula V and VUEngine Platformer share an engine and a symptom — thousands of background-map writes and not one non-zero tile — but not a cause: VUEngine Platformer spins on a single word 1,520,311 times that nothing ever writes, while SPONG drops six virtual calls because the pointer handed to its dispatcher is a background-map address rather than an object. Both Jack Bros builds are a cooperative kernel whose scheduler stops being called. Pacing is not the answer for any of them: swept from 2,000 to 400,000 ticks, SPONG and Formula V return byte-identical numbers at every setting.

  7. frozen

    Frozen is a category, not a bug

    {{FROZEN_N}} games draw a real screen and then never change it. The execution trace records every function entry and dumps the last 64 when a boot chain ends, and no two of these end in the same function — so there is no single fix hiding here. Several fill the trace ring, meaning they execute a great deal and then stop, which is a different problem wearing the same symptom as the ones that give up after ten functions.

  8. glyph

    Character sets that land half-way

    Recorded from earlier passes over these strips: Bound High and V-Tetris render their English warning text correctly and the Japanese text below it as wrong tiles; Tron VB draws the top strokes of its logo and loses the bottoms; Hamburgers renders a full bitmap title and corrupts the small text at bottom left. One character set lands and the other does not.
